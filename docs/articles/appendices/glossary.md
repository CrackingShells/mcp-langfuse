# Glossary

This glossary defines key terms and concepts used throughout the mcp-langfuse documentation. Terms are organized alphabetically for easy reference.

## How to Use This Glossary

Add project-specific terms as the documentation grows. Each entry should include:
- The term in bold
- A clear, concise definition
- Links to related documentation where applicable

---

## A

**API (Application Programming Interface)**
: A set of functions, classes, and methods that a software library exposes for use by other programs.

## B

**Black**
: An opinionated Python code formatter that automatically formats code to a consistent style.

## C

**Conventional Commits**
: A specification for commit messages that provides a structured format for describing changes.

## D

**Docstring**
: A string literal that appears as the first statement in a module, function, class, or method definition, used to document the code.

## G

**Google-style Docstrings**
: A standardized format for Python docstrings that includes sections for arguments, returns, raises, and examples.

## M

**Material Theme**
: A modern, responsive theme for MkDocs that provides professional appearance and enhanced features.

**MkDocs**
: A static site generator designed for building project documentation from Markdown files.

**mkdocstrings**
: A MkDocs plugin that automatically generates API documentation from Python docstrings.

## P

**Pre-commit**
: A framework for managing and maintaining multi-language pre-commit hooks that run before each commit.

**PyPI (Python Package Index)**
: The official repository for Python packages, accessible via pip.

## R

**ReadTheDocs**
: A documentation hosting platform that automatically builds and publishes documentation from Git repositories.

**Ruff**
: A fast Python linter and code formatter that checks for code quality issues.

## S

**Static Site Generator**
: A tool that generates a complete static HTML website from source files, typically Markdown.

---

## Adding Terms

To add a new term to this glossary:

1. Determine the appropriate alphabetical section
2. Add the term in bold followed by a colon
3. Provide a clear, concise definition
4. Include links to related documentation if applicable
5. Keep definitions neutral and factual
